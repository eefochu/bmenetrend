# Nationwide rail and saved station boards

Rail uses the existing public EMMA/MÁVPlusz GraphQL endpoint. The national `vehiclePositions` query requests RAIL and TRAMTRAIN as well as existing bus, metro and HÉV modes. Source namespace `1:` is shared: recognised HÉV services retain `hev` identities; national rail uses `mav`. Unidentified foreign suburban modes are not treated as HÉV. No direct BKK API or server/key is added.

Train line labels (S10, IC, IR, etc.) are separate from the individual train number and service name in `tripShortName`. Font-markup short names are not displayed. Legitimate text arrows, as in DÉLI <- PARTI, remain intact. Search includes train numbers and service names; static rail routes and stations remain searchable without an active vehicle. Vehicles retain source coordinates, heading, speed, next-stop identity, parent station and observation time, with the existing 180-second freshness limit. Positions absent from EMMA are not fabricated.

Train selection uses the real trip's ordered stops and geometry, supports line/direction boarding flows and source-marked departure predictions, and retains valid international stops outside Hungary. A source platform-specific next stop is matched to its declared parent station in the generic rail trip list. BKK platform identities are not equated this way. Train platforms come from each departure's `stop.platformCode`, rather than assuming every train uses the station board's generic platform.

The supplied blue train icon is reused unchanged (it exactly matches the existing bundled artwork). Rail stop dots stay visible down to zoom 9 and rail vehicles down to zoom 7. Other stops/vehicles keep their 12/9 cutoffs. Marker size, dot/icon transitions, layer ordering and source locations follow the shared map presentation. Rail and HÉV remain nationwide when the Volán/BKK local-scope filter is enabled.

## Favourites and departures

The Favourites / Kedvencek bottom tab displays persisted favourite station identities. Tap the existing heart on a departure board to add/remove a station. Visible saved stations show up to four incoming departures and a button for the full board. Each retains line icon, train number/name, source platform, prediction flag, absolute time and compact countdown (Hungarian `4p`, `1ó 3p`; English `4min`, `1h 3min`).

All boards share selectable 30, 60, 120, 180, 240 and 300-minute windows, including nearby departures. The selected window is persisted. EMMA requests 300 departures per pattern, preventing the previous 100-entry cap from truncating frequent services before five hours. Source cancellations/non-pickups are excluded and midnight service-day arithmetic is preserved. Reaching a source limit remains visible as a warning.

Favourite board polling is active only on the foreground favourites tab, every 20 seconds. Visible stations drive requests (at most eight station cards; three HTTP calls concurrently, with up to six platform boards per GraphQL request); recent nearby boards are reused and the cache is bounded. Existing physical platform identities stay separate, but a verified MÁV `_0` aggregation point is queried once instead of separately fetching every numbered track. Per-train platform information remains available. Selected-station and nearby boards use the same batch/cancellation path. Source errors scoped to one GraphQL alias do not discard other successful stations; unscoped errors still fail the batch. Index/cluster selection is cached against stop-catalogue identities rather than recomputed on every clock tick. Stale or unavailable boards are distinguished from valid empty timetables.

## Verification

Captured public source responses from 2026-10-23 in `app/src/test/resources/rail/` cover national and TramTrain positions, S10 trip/line geometry, rail station search, and a Kelenföld board with departures nearly five hours ahead and individual platforms. Unit tests check identity/label isolation, freshness, source coordinates, numeric search, geometry, international stops, parent/platform matching, complete five-hour filtering, saved station selection and compact countdowns. Device validation includes live S36 train 3898 (source position/time, speed, actual route and Budafok → Kastélypark progress), saved Kelenföld boards, train platform numbers and the persisted five-hour selection. The supplied icon is unchanged. A release APK is built with R8.

The emulator exposed HTTP 403 responses during repeated platform requests. The client now shares a cooldown across EMMA consumers for 403/429/503, honours Retry-After (seconds or HTTP date, minimum 60 seconds), and never bypasses it on manual refresh. Denied requests are not immediately retried. Successful recent data retains its original observation/fetch times and normal expiry. Partial/unavailable states remain visible; missing source data is not represented as a successful empty board. Batch requests were independently verified against six real rail/BKK boarding points. Unit tests cover batch failure isolation and cooldown enforcement.
